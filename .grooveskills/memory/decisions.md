| 2026-11-03 | Architectural Wrapper & Adapter Skills Suite | Added 6 architectural skills (`storage-file-adapters`, `auth-rbac-policies`, `controller-orchestration-queues`, `webhook-idempotency`, `caching-rate-limiting`, `env-feature-flags`) | Standardizes object storage, auth/policies, single-purpose action orchestration + queue workers, HMAC webhook verifiers + idempotency, cache-aside + rate limiting, and fail-fast env validation across projects |
| 2026-11-03 | Documentation Standards Skill (`docs-standards`) | Added unified documentation skill covering English documentation, relative POSIX paths, Mermaid diagrams, ADR lifecycle, and intent docstrings | Establishes standard technical documentation practices, eliminates absolute path breakage across IDEs, ensures syntactically safe Mermaid diagrams, and enforces intent-driven docstrings |
| 2026-11-03 | Defensive File Permissions & Transactional Rollback (v1.7.0) | Implemented `safeWriteFileSync` with auto-chmod (0o644) on EACCES/EPERM, `InstallTransaction` journaling, and structured error handling | Prevents dirty/partial repo states on permission issues (like read-only `AGENTS.md`), auto-recovers writable mode when permissible, and rolls back mutations on failure |
| 2026-11-03 | Escalating Atomic Replace, Preflight Write Check & English CLI (v1.7.1) | Added `inspectFileAccess`, atomic file replacement (`temp + rename`) in `safeWriteFileSync` for root-owned files in writable directories, `runPreflightWriteCheck`, honest rollback failure tracking (`isClean` / `failures`), and restored 100% English CLI copy | Resolves `EACCES` when `AGENTS.md` is owned by `root` in a user-writable directory without requiring `sudo chown`, fails before Stage 1 when recovery is impossible, avoids rewriting untouched files on rollback, and keeps CLI output strictly in English |
| 2026-11-03 | Universal Descriptive Naming Standard | Added Golden Rule #8 to `best-practices` prohibiting single-/two-letter and cryptic identifiers (`d`, `a`, `s`, `p`, `tx`, `err`, `res`) across codebases | Ensures maximum legibility, zero ambiguity in callbacks and loops, and enforces explicit domain intent in all codebases managed by GrooveSkills |
| 2026-11-08 | Mandatory README Updates on Scope Changes | Standardize mandatory README.md synchronization whenever functionality, CLI commands, flags, or project structure are added or removed | Keeps user-facing documentation aligned with code changes in real-time, preventing stale guides, obsolete CLI documentation, or outdated directory structures |
| 2026-11-08 | Unified Adversarial Security Audit Skill (v1.11.0) | Unified Cloudflare 6-Phase Audit, NVIDIA SkillSpector 17 categories, and Strix OWASP API & Root-Cause Remediation into universal \`security-audit\` skill and ODD Post-Task Security Gate | Automates trust-boundary verification at the conclusion of every task, secures agent/MCP definitions, and provides on-demand 6-phase adversarial audit with regression PoCs |
| 2026-11-08 | Chronological Task Naming & Auto-Normalization (v1.12.0) | Enforce `YY-MM-DD-<slug>.md` task naming convention by default and added `normalizeTaskFileNames` | Guarantees chronological file sorting across task records, auto-converts non-conforming filenames during harness updates, and avoids naming collisions |
| 2026-11-08 | Relative Symlinks for Agent Skills & Auto-Migration (v1.13.0) | Replaced copied reference folders in `.agents/skills/`, `.claude/skills/`, and `.gemini/skills/` with relative symbolic links (`../../.grooveskills/skills/<skill>`) created with junction type, and added auto-migration for legacy projects | Eliminates duplicate content while preserving IDE discoverability, keeps skills folders open for user custom skills, guarantees cross-platform symlink reliability, and supports transactional rollback |
| 2026-11-09 | Standalone Zero-Footprint Security Audit (v1.14.0) | Added standalone `grooveskills audit` CLI command executing 5 security coverage units without writing files | Enables instant zero-footprint adversarial security audits with actionable remediation recipes and exit codes |
| 2026-11-09 | Strict Atomicity & Hono Action Architecture (v1.15.0) | Enforced 1 method/function per file, inline interfaces restricted exclusively to component Props, banned `src/domains/` in favor of `src/actions/{domain}/`, and standardized direct domain Hono routes | Eliminates agent architectural drift, enforces clean SRP per file, and standardizes route delegation to Actions directly or via Pipelines |
| 2026-11-09 | 1 DB Query per Action & Mandatory Pipeline Chaining (v1.16.0) | Standardized rule that all DB calls must be isolated in atomic Actions (max 1 query/mutation per Action), banned monolithic use-case actions (`register-user.action.ts`), and mandated `Pipeline.send().through([...])` in routes | Prevents god-actions in business layer, enforces clean atomic testability, and standardizes route pipeline sequencing across all skills |
| 2026-11-10 | Next.js & Vinext Server Architecture (`nextjs-architecture`) | Added `nextjs-architecture` skill with 100% server pages, server-side initial data loading via Server Actions, client hooks restricted to interactive logic, loading.tsx skeletons, URL state, and GroovePack pipeline; auto-selected on Next/Vinext and mutually exclusive with `react-create-page` | Eliminates coordinator hook antipattern in Next.js, enforces server-first data fetching, guarantees zero manual creation of centralized GroovePack packages, and provides native Cloudflare support via Vinext |
| 2026-11-10 | Installed Skills Preselection & Full Uninstallation | Preselected already installed skills in interactive prompt, added confirmation on deselection, and implemented full removal from canonical store, agent links, cursor rules, and config.json | Preserves user choice between runs, prevents accidental skill proliferation, cleanly uninstalls unselected skills across all agents, and safeguards custom user skills |
| 2026-11-11 | Mandatory Semantic Version in config.json & status Command (v1.18.0) | Replaced numeric `version: 1` in `.grooveskills/config.json` with semantic package version string (e.g. `"1.18.0"`), enforced mandatory updates on every run, and added `grooveskills status [path] [--json]` | Guarantees clear traceability of the installed GrooveSkills version in any project, detects outdated installations without re-installing, and documents that `version` must always be updated on releases and installation runs |
| 2026-11-11 | Daily Bitacora Max 10 Items per Day Compaction Rule | Established strict rule that `.grooveskills/bitacora/YYYY-MM.md` date sections (`YYYY-MM-DD`) must not exceed 10 list items; agents must compact and merge related bullets when exceeding 10 items | Prevents bloated bitacoras, maintains concise summaries for external task tracking (Jira/Linear), and eliminates nested sub-bullet clutter |
| 2026-11-12 | Canonical Versions File & AI Agent Update Prompt | Introduced `.grooveskills/VERSIONS.md` documenting recent releases (v1.14 to v1.18.1), and dynamic copyable update prompt instructing the AI agent to review changes before proposing plans | Eliminates hardcoded change descriptions in prompt strings, ensures AI agents reference local version notes, prevents unauthorized code modifications prior to plan approval, and displays clean prompt during updates |
